For AI agents

How to write correct code with tonal. Written for coding agents, useful for people too.

This page is for coding agents (and people) writing code that uses tonal. Read it before writing tonal code, then look up the functions you need in the API list, which has every function with its exact signature and return type. Don't guess function names: tonal's API has changed over the years, so names you remember may be gone or deprecated. Every page of these docs is also available as markdown: add .md to its url, or start from llms.txt.

The API list is also in the npm package, at node_modules/tonal/llms-api.txt, matching the version you have installed.

Import

tonal exports one namespace per module (Note, Interval, Chord, ChordType, Scale, ScaleType, Key, Mode, Midi, Pcset, Progression, RomanNumeral, Range, Collection, Voicing, VoiceLeading, TimeSignature, DurationValue, RhythmPattern, AbcNotation) and a few top-level functions (note, interval, transpose, distance). Each namespace is also its own npm package: import * as Chord from "@tonaljs/chord". Use tonal unless bundle size matters. In a browser without a bundler, tonal/browser/tonal.min.js defines a Tonal global.

Don't use the deprecated namespaces Tonal, PcSet, ChordDictionary, ScaleDictionary and VoicingDictionary: use the top-level functions, Pcset, ChordType, ScaleType and Voicing (with options or templates).

How tonal works

Everything is a string or a plain object. Notes are strings ("C4", "Eb5", "F#"), intervals are strings ("5P", "3m"), chords and scales are named by strings ("Cmaj7", "D dorian"). Functions that parse a name return a plain object with its properties. There are no classes and nothing mutates.

Invalid input never throws. It returns an empty value, so check it:

Number results are null, undefined or NaN depending on the function: the API list shows which. NaN passes typeof x === "number", so test with Number.isFinite(x).

Notes and pitch classes. A note with an octave ("C4") is a note; without one ("C") it's a pitch class. Most functions keep what they're given: transposing a pitch class gives a pitch class, and a chord or scale with a plain tonic has pitch-class notes. Octave 4 is the one with middle C ("C4" is midi 60, "A4" is 440 Hz).

Intervals are written number first, quality second: "5P", "3M", "3m", "4A", "5d", "-2M" (descending). Quality first ("P5", "M3") is also accepted as input, but tonal always returns number first:

Spelling is kept. Transposition follows the interval, so the result can have double accidentals or E#. Use Note.simplify or Note.enharmonic when you want the simplest name:

MIDI numbers have no spelling, so converting them to names needs a choice. Note.fromMidi uses flats, Note.fromMidiSharps uses sharps:

Chords

  • Don't put an octave in a chord name. Chord.get("C4maj7") is empty, and Chord.get("C4") is not C at octave 4 but C quartal (["C", "F", "Bb", "Eb"], "4" is an alias of the quartal chord). For notes with octaves, pass the tonic separately: Chord.notes("Cmaj7", "C4") or Chord.notes("maj7", "C4").

  • Chord names accept the usual symbols and aliases ("CM7", "CΔ", "C^7", "C-7", "Cø", "Cm7b5", "C7(b9,#9)", "Co9", and spaced qualifiers like "Cm7 b9", which is "Cm7b9"). Check .empty for symbols you aren't sure of. ChordType.get("maj7").aliases lists the aliases of a type.

  • Chord.detect returns names, best match first, and the lowest note is the bass. A major triad is named "CM", not "C":

    Chords played without their fifth are named with no5 (Chord.detect(["C", "E", "B"]) is ["Cmaj7no5"]). Pass { missingFifth: false } for names of listed chord types only, or { assumePerfectFifth: true } to get "Cmaj7".

  • Chord degrees by name (counted from the major scale of the root, as in chord symbols): Chord.formula, Chord.noteOf, Chord.degreeOf. Chord.degreesByImportance sorts them by how much they define the chord, to choose which notes to keep when there are fewer voices than chord tones:

  • Chord.get(name).complexity (or ChordType.get(type).complexity) is the number of notes added to a triad plus two for each chromatic note (outside the major scale that holds most of the chord, as spelled): m is 0, m7 1, dim7 3, 7b9#11 7. Sort by it to list common chords first.

  • Chord.degrees and Chord.steps are different: they count chord notes by position (1 or 0 is the root), not degrees by name. Chord.degrees("C")(3) is "G", the third note of the chord.

Scales, modes and keys

  • Scale names are full names: "C major", "A minor", "C maj" is empty. Scale.names() lists all of them. A scale without a tonic ("major") has intervals but no notes.
  • Key.majorKey and Key.minorKey return everything about a key at once (scale, triads, seventh chords, harmonic functions, chord scales, secondary and substitute dominants). A minor key has three scales: natural, harmonic and melodic. In secondaryDominants and similar lists, "" means the degree has none.
  • Scale.outside(scale, chord) lists the chord notes that aren't in the scale, spelled as in the chord: Scale.outside("C major", "Bb7") is ["Bb", "Ab"], and [] when the chord fits. To list the chord types that fit a scale, use Scale.scaleChords; for the chord on each degree, Scale.chords.
  • Mode is about the seven Greek modes (Mode.names()); for other scales use Scale. Scale.modeNames("C harmonic major") names the modes of any scale, and a scale type that is a mode of a parent scale has family and degree: ScaleType.get("dorian b5") is degree 2 of "harmonic major".

Roman numerals and progressions

Lowercase numerals are minor ("ii7" is the same as "IIm7"). Applied chords such as "V7/V" are supported. RomanNumeral.get parses one numeral into its parts.

Voicings

The chord symbol says which notes the chord has; the options say how to play them: voices (a number, or a range per voice), extensions ("available" or a list of degrees), bass ("none", "root" for a bass part, "external" for a bass player), range, top (a melody note), previous, anchor. The rules are in the API list. [] means the chord isn't valid or no voicing fits.

Calling Voicing.get, search or sequence with a range array as the second argument uses the old dictionary voicings (VoicingDictionary), which are deprecated, as is VoiceLeading.topNoteDiff: use the options object and previous (or VoiceLeading.path).

VoiceLeading measures how far the voices move between two voicings (notes with octave) and finds the smoothest path through candidate voicings. It works with any voicings, including ones you build yourself:

distance and pcDistance return null, not a number, for an empty voicing or a note without octave.

Time

tonal describes where things are in musical time, never when they play: there is nothing in seconds, no tempo-based timing, no scheduling and no audio. TimeSignature, DurationValue and RhythmPattern cover meters, note values and rhythm patterns. Use an audio or scheduling library for playback.

Common mistakes

  • Using functions that don't exist or are deprecated: check the API list. Functions marked [deprecated] there still work, but write new code with their replacement.
  • Not checking for empty results: an invalid name gives "", [], null or an object with empty: true, and the error shows up later.
  • Expecting octaves from chords and scales named with a pitch class, or putting the octave inside a chord name.
  • Comparing notes as strings: "C#4" and "Db4" are different strings for the same key on a piano. Compare Note.midi(a) === Note.midi(b) for the same pitch, or Note.chroma(a) === Note.chroma(b) for the same pitch class.
  • Writing "C" for a C major chord when comparing with Chord.detect results, which name it "CM". Compare chords by their notes or with Chord.get(name).symbol instead of by name.
